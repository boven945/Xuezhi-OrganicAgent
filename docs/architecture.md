# 系统架构与组件职责

## 1. 状态与设计原则

本文件描述目标架构与当前实现的对照。**后端七个模块已有可运行实现**
（chem / llm / agent / rag / knowledge-data / api / speech），
API 网关已可提供 HTTP 服务；前端尚未提交。
`backend-speech` 已实现 Edge-TTS 合成与 Fay 推送（两者均可降级），
但**尚未开API 端点**——音频交付方式待决策（H21）。
各模块测试数见 `interface-contract-verification.md` 与
`development-log-2026-10.md`。

设计原则：高中课程边界优先；模型负责语言理解与组织而不是单独担任化学验证器；工具调用遵循显式输入/输出约束；语音、数字人和动画均不应阻断文本答复；云端与本地模式共享领域行为和验收集。

## 2. 逻辑组件

| 层 | 组件 | 技术 | 职责 |
| --- | --- | --- | --- |
| 表现层 | Web 应用 | Vue 3、Vite、TailwindCSS | 文本输入、答案呈现、加载/错误状态、动画和 Fay 画面集成 |
| 可视化层 | 分子视图 | Three.js、Molstar | 使用后端提供并通过校验的结构数据呈现球棍/填充视图及变化动画 |
| 通信层 | HTTP 客户端 | Axios | 请求 FastAPI、处理超时/取消和服务错误 |
| API 网关 | 应用服务 | FastAPI、Uvicorn、Pydantic | 输入校验、请求关联、路由、限流策略接入和响应整形（**已实现**，见 `interface-contract-verification.md`） |
| Agent 编排 | 工具调度器 | LangChain、自定义 MCP 调度层 | 任务规划、工具选择、参数校验、结果回传、超时和失败隔离 |
| 模型适配 | LLM Provider | langchain-openai | 以 OpenAI 兼容协议连接华为 ModelArts MaaS 或本地兼容推理服务 |
| 知识检索 | RAG | ChromaDB、sentence-transformers | 过滤、嵌入、召回高中课程范围内的知识条目 |
| 化学工具 | Chem Engine | RDKit | SMILES 解析、结构检查、受支持的分子属性计算和反应规则校验 |
| 语音/数字人 | Fay 适配 | Edge-TTS、自研通信脚本、Fay 服务 | 生成语音并转发数字人需要的展示/唇形数据。**已实现**：`SpeechService.speak()` 保证不抛异常，TTS 与 Fay 均可降级；不接 10002 WebSocket（本项目前端不驱动数字人形象） |
| 支撑 | 配置、日志、数据处理 | python-dotenv、Loguru、requests、NumPy、Pandas | 配置读取、诊断日志、HTTP 集成和批量数据处理 |

系统使用 ChromaDB 作为向量数据库，LLM 底座为华为 openPangu。

## 3. 请求主流程

1. 学生通过 Vue 页面提交文本问题。
2. Axios 将请求发送给 FastAPI；API 执行输入校验并建立请求关联标识。
3. Agent 根据问题决定是否检索高中知识、解析分子或调用其他获准工具。
4. MCP 调度层验证工具名与参数，调用 ChromaDB、RDKit 等工具并收集结果。
5. openPangu 根据问题、可信检索片段和结构化工具结果组织回答；工具调用和最终输出均需校验。
6. FastAPI 返回解释、来源和可选可视化数据；前端展示文本及可用的分子视图。
7. 用户启用语音且服务可用时，Fay/Edge-TTS 支路处理讲解文本；失败不应抹除文本答复。

是否采用同步响应、流式输出、任务轮询或推送通道，须在实现前按延迟和 Fay 服务能力确定；不得据此推断具体 API 协议。

## 4. 模型运行模式

| 模式 | 模型 | 连接方式 | 适用场景 | 关键依赖 |
| --- | --- | --- | --- | --- |
| 云端开发 | openPangu-2.0-Flash（ModelArts MaaS） | OpenAI 兼容 API | 日常开发和联网演示 | requirements_cloud.txt、有效服务配置和网络 |
| 本地离线演示 | openPangu-7B-Instruct，AWQ 4-bit | 本地推理适配器 | 比赛现场断网演示 | 完整依赖、模型权重、兼容的 CUDA/PyTorch/AutoAWQ 组合及足够显存 |

模型名称、上下文能力、原生 Function Call 支持和硬件适配均应以实际租户权限、服务文档、模型文件及部署测试为准。512K 上下文等指标是目标服务描述，不构成端到端请求长度保证。

## 5. 工具边界与结果处理

- 所有模型提出的工具调用都必须由调度层白名单、参数 schema 和超时策略约束。
- RDKit 验证范围应明确区分语法解析、结构合法性、属性计算和反应规则覆盖；通过 SMILES 解析不等于反应机理正确。
- RAG 片段应保留来源 ID、教材/文档版本、章节/页码（如可获得）和审核状态。
- 工具失败要以结构化状态返回；不可用服务不得被静默替换为模型臆造结果。
- 动画仅消费已验证且前端认识的结构化分子数据，不直接执行模型返回的脚本或 HTML。

## 6. 可观测性与可靠性

每次请求应具备关联 ID、模式标识、阶段耗时、工具结果状态和可诊断错误码。日志不得包含 API 密钥、完整认证头或不必要的原始学生文本。指标至少覆盖请求数、错误率、模型延迟、RAG 检索状态、化学工具失败、语音服务状态和本地显存/加载失败。

模型、RAG、RDKit、动画、TTS/Fay 应有独立超时与失败路径。推荐将文本回答设为主交付，将动画和语音视为可降级能力；最终行为须通过故障演练确认。

## 7. 架构决策待确认

- MCP 调度层采用的协议版本、传输方式、工具 schema 与权限边界。
- API 路由、认证方式、会话存储、流式/异步任务协议。
  **部分推进（2026-10-04）**：路由与传输方式已定并实现——同步 + SSE 并存，
  5 个路由见 `interface-contract-verification.md`。
  **仍未定**：认证方式（当前无鉴权）、会话存储（服务端无状态）。
  **已知限制**：SSE 是阶段事件而非逐 token 流（`AgentLoop` 同步迭代）。
- Fay SDK/服务的版本、通信协议、端口及音视频数据流向。
- 本地模型服务适配器、权重分发/校验方式以及 RTX 5070 显存实测。
- ChromaDB 部署方式、持久化卷、备份周期和并发访问策略。
- 服务部署位置、TLS/反向代理、监控与告警系统。
