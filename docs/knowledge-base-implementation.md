## 2. 版权边界（本模块最重要的约束）

联网检索了相关法律实践与行业规范，结论明确：

- **台湾高校图书馆公告**：不得将电子书全文导出建立数据库供 AI 训练
  或知识库建置之用；并明确「合理使用并非所有教育用途皆适用」。
- **台湾经济部智慧财产局令函**：使用他人原文书籍作线上教材，
  除合理使用情形外应取得著作权人同意，**建议向出版社或作者取得授权**。
- **大陆实务观点**：将完整著作或大比例内容输入系统、
  或使生成内容可替代原著功能，会显著提高侵权风险；
  较安全的做法是「避免输入完整著作，优先使用节录内容」。

因此本模块的设计：

1. **仓库内不含任何教材原文**。`.gitignore` 已排除
   `data/knowledge/raw/`、`data/knowledge/*.pdf` 等路径（实测验证：
   源材料与索引产物被忽略，自编语料 `dev-corpus.json` 可提交）。
2. **许可白名单是硬闸门**。`ALLOWED_LICENSES` 共 6 项，
   **不含 `unknown` 之类的兜底值**——无法确认许可的内容无法通过。
   缺许可字段直接拒绝入库。
3. **仓库语料全部标记 `project-authored` 或 `internal-dev-only`**，
   内容为项目自编的通识性表述，不是教材原文。
4. 生产语料须走 `licensed-official`，并**留存授权凭证编号**。

> 这是我目前识别到的**最大外部风险**：整个项目的演示内容依赖教材，
> 而教材的合理使用边界在 AI 场景下远不如传统教学场景清晰。
> 建议在比赛前明确取得授权，或改用自编讲义体系。

## 3. 切分策略的依据（联网核实，非记忆）

### 3.1 为什么用递归字符切分而非语义切分

**关键证据**：Vectara 研究（NAACL 2025, arXiv:2410.13070）测试
**25 种切分配置 × 48 个 embedding 模型**，结论是
**切分配置对检索质量的影响 ≥ embedding 模型的选择**。
同一语料下最优与最差策略的召回率差距可达 **9%**（Chroma 数据）。

FloTorch 2026 基准（50 篇论文、90 万 token、10+ 学科）的端到端答案准确率：

| 策略 | 准确率 |
| --- | --- |
| **递归字符切分 512 token** | **69%** |
| 固定大小 512 token | 67% |
| 语义切分（LLMSemanticChunker） | **54%** |

**语义切分更差的原因**：产出平均 **43 token** 的碎片，
检索命中但上下文不足，模型答不出。

**这直接改变了本项目的评估取向**：不能只看检索命中。
FloTorch 强调「召回率」与「答案准确率」必须分开看，
「检索得到但答错」仍是坏切分。因此
`knowledge-base.md` §6 要求教师做端到端核对，
而非仅看检索指标（H18）。

### 3.2 为什么按字符而非 token

`RecursiveCharacterTextSplitter` 默认 `length_function=len`，
即**字符数**。中文场景下 512 字符约 350-500 token，
恰好落在 bge-small-zh 的有效区间（实测维度 512、max_seq_length 512）。
强行按 token 计数须额外引入分词器并校准，
而收益在本项目语料规模下不可验证。

### 3.3 中文分隔符

中文句子终止符是 `。！？；` 而非英文的 `.!?`。
沿用 LangChain 默认的 `["\n\n", "\n", " ", ""]` 会让切分点
落在中文句子中间。本模块的 `CN_SEPARATORS` 纳入中文终止符，
且段落边界优先级最高。

### 3.4 重叠的作用边界

重叠**只能缓解**边界割裂，**不能保证**跨块内容完整：
若一个关键实体出现在 2000 字段落中部，该段落被切成两块、
只重叠 100 字，则该实体只存在于其中一块。

**真正的保障是让语义单元本身完整**——这正是
`chunk_by_section` 存在的理由：教材有明确的章/节/小节结构，
先按结构切，多数小节天然落在 512 字符内。

### 3.5 表格与公式不做细切

表格被切成多块后行列关系必然损坏。
本模块在切分**前**检测表格标记（≥2 个）与公式特征（≥3 个符号密度），
命中则整块保留。密度阈值是必要的：单个箭头或上下标
不应使整节散文被当作公式保护。

## 4. 实测数据（2026-10-04）

真实 `BAAI/bge-small-zh` + `chromadb` + 6 条开发语料，7 个探针：

| 指标 | 值（K=5，无阈值） |
| --- | --- |
| Recall@5 | **1.0000** |
| Hit Rate@5 | **1.0000** |
| MRR | **1.0000** |
| NDCG@5 | 0.9836 |
| Precision@5 | 0.2571 |

逐条结果：7 个探针**全部首位命中**（recall=1.00），
包括跨主题查询「有机化学中的取代反应有哪些」。

结果写入 `data/eval/retrieval-eval.json`（产物目录，不入 Git）。

### 4.1 一个必须说明的观察：阈值在当前规模下不起作用

多阈值对比：

```
thr=None:  recall=1.0000 precision=0.2571 mrr=1.0000
thr=0.5:   recall=1.0000 precision=0.2571 mrr=1.0000
thr=0.7:   recall=1.0000 precision=0.2571 mrr=1.0000
thr=0.85:  recall=1.0000 precision=0.2571 mrr=1.0000
```

**四个阈值的结果完全相同**。原因：语料仅 6 条，
所有片段与查询的余弦距离都远低于 0.85，阈值筛选未剔除任何一条。

**这不表示阈值已验证**，只表示**当前样本量不足以观察阈值效果**。
要观察阈值的作用，需要语料达到数百条量级。
因此 `KnowledgeStore.query` 仍**不设默认阈值**，
生产阈值仍待标注问答集实测确定（C5/H18）。

### 4.2 指标不是质量结论

`Precision@5 = 0.2571` 看着低，但这只是因为
`K=5 > 语料条数 6`，分母被人为放大——**这不是系统的缺陷**，
是样本规模与指标定义的匹配问题。

**这组数据唯一的价值是**：验证评估链路可运行、
给出基线数值。质量结论须由化学教师用标注问答集做（H18）。

## 5. 测试结果

### 5.1 单元测试：108/108 通过

- **切分**（33 项）：空白归一化但不合并换行、中文终止符保留、
  无内容丢失、重叠生效、确定性、表格与公式检测、
  层级路径、碎片合并不跨级
- **准入**（39 项）：schema 校验、必填字段、许可白名单闸门、
  审核状态、课程范围、重复 id、部分失败不产出片段、
  仓库语料文件的回归保护
- **评估**（36 项）：五个指标的计算正确性、
  K 之外不计入、Precision 分母为 K、RR 取首个命中、
  空样本返回 `None` 而非 0、不给出推荐阈值

### 5.2 端到端：7 项通过 + 1 项按设计跳过

（跳过项为超纲查询，在当前阈值下召回了片段，
须由教师判断是否属于误召回——**这正是需要人工判断的部分**。）

### 5.3 全量：331 通过 / 26 跳过

## 6. 测试暴露的缺陷（7 处，全部修复）

| # | 缺陷 | 根因 | 严重度 |
| --- | --- | --- | --- |
| 1 | **结构保护完全失效** | 把表格/公式检测写在 `len(body) <= max_chunk_size` 分支**内**，超长表格（133 字符 > 60）绕过保护被细切 | **高**（§5 保护形同虚设） |
| 2 | **标题正则捕获不全** | `.*` 放在 `title` 组的交替分支**之外**，捕获到的只有编号「第六章」，标题文字「有机化学基础」全丢 | **高** |
| 3 | **层级推断错误** | `_infer_depth` 把 `一、` 与 `第N节` 同判为 2，导致 `第三节 酯化反应` 被 `一、反应的定义` 覆盖，节层消失 | **高** |
| 4 | **碎片跨级合并** | 短块无条件并入上一块，`一、反应的定义` 下 20 字正文被并到上一小节，多层级压平成一块 | **高** |
| 5 | `looks_like_formula` 漏判 `\alpha` | 正则 `\\[a-zA-Z]+\{` 强制要求紧跟 `{`，而无参 LaTeX 命令不满足 | 中 |
| 6 | `suggest_threshold` 崩溃 | 键含 `None`（不过滤），`sorted()` 时 None 与 float 比较抛 TypeError | 中 |
| 7 | 6 个文件共 22 处 ``xxx.md` 引用格式错误 | 历史遗留（应为 `` `xxx.md` ``） | 低 |

第 1-4 项都是**设计层面的问题**，单元测试层面看不出
「保护逻辑写了但位置错了」「层级被覆盖」，
必须用**真实教材风格文本**做E2E 才暴露。

**教训**：`chunk_by_section` 这类涉及结构的函数，
单元测试必须用**教材风格的多层级文本**，而非短小单层样例。

## 7. 遗留与后续

| 项 | 说明 |
| --- | --- |
| **教材 PDF 解析未实现** | 需 PyMuPDF（速度）或 pdfplumber（表格）提取文本。实测选型数据：PyMuPDF 文本提取比 pdfminer.six 快 28倍；但**PyMuPDF 是 AGPL-3.0**，商业闭源需购买许可，pdfplumber 是 MIT |
| **版权授权未解决** | 见 §2。这是最大外部风险（D3） |
| **阈值未确定** | 见 §4.1，当前样本量不足以观察（C5/H18） |
| **语料规模过小** | 6 条不足以评估。生产需数百条量级 |
| **无混合检索** | 中文关键词检索需 BM25 + jieba 分词。当前纯向量对精确术语召回弱。联网核实：BM25 对专有名词/错误码强，向量对语义泛化强，两者互补（RRF 融合，k=60） |
| **无重排序** | 联网核实：多路召回后用 reranker 重排可提升准确率。当前 top_k 较小，收益待评估 |
