# 部署与运维手册

## 1. 当前可运行状态

当前仓库仅包含文档和 Python 依赖清单，没有前端源码、FastAPI 入口、MCP 工具实现、Fay 通信服务或 Dockerfile。因此本手册提供环境准备和发布基线，不声称当前仓库已能启动完整系统。代码入口、实际命令、端口、健康检查地址和配置键须在实现后回填并实测。

## 2. 环境基线

| 组件 | 基线 |
| --- | --- |
| Python | 3.12 |
| Node.js | 18+ |
| 化学依赖 | RDKit，推荐从 conda-forge 安装（2026.03.6 已提供 py312 构建） |
| 云端开发 | 华为 ModelArts MaaS 账号/授权、网络连通和经核实的 API 配置 |
| 本地离线 | openPangu-7B-Instruct 权重、AWQ 4-bit 推理依赖、兼容的驱动/CUDA/PyTorch 组合 |
| 可选组件 | Docker；Fay 服务及 Edge-TTS 的可用运行环境 |

RTX 5070 是目标演示硬件，不代表未经测试的显存、吞吐或兼容性保证。发布前应记录驱动、CUDA、PyTorch、Transformers 和 AutoAWQ 的实际组合及测试结果。

## 3. Python 依赖选择

- 本地模型模式：使用根目录 requirements.txt。
- 云端 API 开发：使用 requirements_cloud.txt，避免安装本地模型推理包。
- RDKit 不在 pip 依赖中启用；建议在激活目标 Conda 环境后单独安装：

    conda install -c conda-forge rdkit

- 本地模式的 PyTorch 应按目标 CUDA 版本选择适配构建。不要假设依赖文件中的最低版本约束能自动选出合适的 CUDA wheel。
- requirements 文件使用下限版本，不是可复现锁定文件。正式发布需验证依赖组合并生成经过审查的锁定/约束方案。

## 4. 云端开发发布流程

1. 准备 Python 3.12、Node.js 18+ 和隔离环境。
2. 安装 requirements_cloud.txt 与 Conda RDKit。
3. 在华为云控制台核实 MaaS 模型 ID、API endpoint、认证方式、配额、区域和服务条款。
4. 将认证信息放入部署平台的密钥管理，不写入仓库、镜像层、前端构建产物或日志。
5. 部署后端和前端源码；具体启动命令、监听地址和反向代理规则必须由实现补充。
6. 执行健康检查、代表性高中化学回归集、工具调用测试、超时/限流测试和凭据泄漏检查。
7. 记录版本、依赖锁定信息、模型标识、知识库版本、部署者和回滚目标。

## 5. 本地离线演示准备

1. 提前下载并校验获准使用的 openPangu-7B-Instruct AWQ 4-bit 权重；记录模型版本/来源及校验和。
2. 在目标机器验证 NVIDIA 驱动、CUDA、PyTorch、Transformers、Accelerate、AutoAWQ 的兼容组合。
3. 使用完整依赖清单安装环境并通过 RDKit 冒烟验证。
4. 在断网条件下验证模型加载、一次完整文本问答、RAG 检索、分子解析、前端显示和必要的语音降级行为。
5. 确认模型文件、知识库和日志可在离线环境读取，演示数据不含真实学生个人信息。
6. 准备模型加载失败、显存不足、结构解析失败和可视化不可用时的演示降级方案。

如果 Fay 或 Edge-TTS 依赖外网，则不能称完整多媒体能力为离线可用；应提前实测网络依赖并在演示材料中说明。

## 6. 配置与密钥管理

本仓库尚无经实现确认的环境变量名称，因此不提供猜测的 .env.example。后续应由配置代码和部署配置共同定义配置清单，至少说明：配置键、用途、必需/可选、默认行为、密钥级别、环境覆盖方式和验证方式。

所有密钥通过本地未跟踪配置或部署平台密钥管理注入。禁止将真实 .env、MaaS API Key、模型访问令牌或服务凭据提交到 Git。配置缺失时服务应快速失败并给出不含密钥的错误说明。

## 7. 发布前检查清单

- [ ] 前端和后端使用的 API 契约版本一致。
- [ ] Python、Node、RDKit、CUDA/PyTorch 版本及依赖锁定记录完整。
- [ ] MaaS 配额、超时、速率限制和密钥轮换流程已验证。
- [ ] 本地模型权重来源、授权、完整性和断网加载已核验。
- [ ] 课程知识库版本、审核记录和回滚包已确定。
- [ ] 日志脱敏、访问控制、TLS 和备份策略已经检查。
- [ ] 核心问答、边界拒答、无效 SMILES、下游超时和服务降级用例通过。
- [ ] 已验证停止/重启、健康检查、告警、备份恢复和回滚流程。

## 8. 运维与故障排查

| 现象 | 优先检查 | 处置原则 |
| --- | --- | --- |
| 云模型请求失败 | endpoint、授权、区域、配额、网络、超时 | 检查服务端错误和关联 ID；不得打印认证头；短暂错误按有上限的退避策略重试 |
| 本地模型无法加载 | 权重路径/校验和、显存、CUDA 与 PyTorch 兼容性 | 记录版本及资源状态；优先恢复已验证环境，不临时升级生产依赖 |
| RDKit 安装/导入失败 | Conda 环境是否激活、Python 版本、安装来源 | 在目标环境中用 conda-forge 安装并记录求解结果 |
| 检索不到内容 | 知识库版本、向量索引状态、embedding 模型一致性、过滤条件 | 不以模型常识伪装成有来源答案；回滚至已验证索引 |
| 动画错误 | SMILES 解析结果、结构数据 schema、前端支持的表示类型 | 保留机理文本，隐藏无效视图并给用户清晰提示 |
| Fay/TTS 不可用 | 服务进程、网络、音频格式和 SDK 协议 | 关闭多媒体支路，保留文本答复；告警并记录状态 |

故障响应必须遵循项目实际的监控和升级流程；系统接入监控后，在此补充责任人、SLO、值守渠道和服务恢复目标。
