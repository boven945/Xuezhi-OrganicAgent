# 官能团 SMARTS 精度修正：I5 实测记录

本文记录 2026-10-04 对 `backend-chem` 官能团识别的修正。

- 分支：`fix/chem-smarts-hydroxyl-precision`（从 `main` 切出）
- **测试：全量 574 通过 / 36 按设计跳过**（chem 42 → 72，新增 30 项）

## 1. 问题：羟基的定义过宽

原定义：

```python
("羟基", "[OX2H]")
```

`[OX2H]` 只描述"连两个原子且带一个氢的氧"。
这个定义**不区分氧连的是哪种碳**，导致三类结构全部误报：

| 结构 | 是否应含羟基 | 原实现 |
| --- | --- | --- |
| 乙醇 `CCO` | 是（醇羟基） | ✅ 命中 |
| **乙酸 `CC(=O)O`** | **否**（羟基在羧基里） | ❌ **误报** |
| **苯甲酸 `OC(=O)c1ccccc1`** | **否** | ❌ **误报** |
| **甘氨酸 `NCC(=O)O`** | **否** | ❌ **误报** |

**为什么这是必须修的化学正确性问题**：学生看到"乙酸含羟基"，
会推断羧酸是醇——而醇与羧酸在高中是**性质迥异**的两类化合物
（乙醇不与碳酸钠反应、不显酸性；乙酸则放CO₂）。

实测确认误报的羟基与羧基命中的是**同一个氧原子**，
说明来源确实是羧基里的 O-H。

## 2. 联网查证：三种候选写法

搜索得到的权威参考（chemistry.stackexchange 的高票答案、
DataChem2025 SMARTS Primer、SMARTS42 特征集）给出三种写法。
**它们并不等价**，所以逐一实测而非凭选第一个。

## 3. 实测对比（16 个高中常见结构）

| 写法 | 羧酸误报 | 苯酚漏报 | 结论 |
| --- | --- | --- | --- |
| `[OX2H]`（原） | 乙酸、苯甲酸、甘氨酸 | 无 | ❌ 误报 |
| `[#6X4][OX2H]` | 无 | **苯酚** | ❌ 漏掉苯酚 |
| `[OX2H][CX4;!$(C([OX2H])[O,S,#7,#15])]` | 无 | **苯酚** | ❌ 漏掉苯酚 |
| `[OX2H][CX4&!$(C([OX2H])[O,S,#7,#15]),c]` | 无 | 无 | ✅ 全部正确 |

**后两种为什么漏掉苯酚**：它们的碳约束是 `[CX4]`（sp3 碳），
而酚羟基连的是**芳香碳**（sp2）。用它们排除羧酸的同时，
把苯酚一起排除了。

**这不是"更好的写法"，是把一个错误换成另一个错误。**

## 4. 最终方案：拆成两条

```python
("醇羟基", "[OX2H][CX4;!$(C([OX2H])[O,S,#7,#15])]"),
("酚羟基", "[OX2H][c]"),
```

### 语义分解

| 片段 | 含义 |
| --- | --- |
| `[OX2H]` | 氧，连两个原子、带一个氢 |
| `[CX4]` | 相连的碳必须是 sp3（总连接度 4） |
| `!$(C([OX2H])[O,S,#7,#15])` | 递归否定：排除"碳同时连羟基与 O/S/N/P"，即缩醛、半缩醛、糖 |
| `[c]` | 相连的碳是芳香碳 → 这是**酚**的定义 |

递归否定的影响范围（实测）：
乙醇、乙二醇、环己醇、叔丁醇、氨基乙醇**均正常命中**，
只排除缩醛类结构——这在高中范围内不涉及，不构成漏报。

### 为什么拆两条而不是用第四种写法

第四种（`[CX4&!$(...),c]`）也能全部通过 16 个用例，
但它把醇与酚**合并成一个"羟基"**。而本项目语料
（`org-alcohol-phenol-difference`）把"醇羟基 vs 酚羟基"
列为**高频易错点**，明确要求区分：

> 醇羟基与酚羟基的差异是两个高频易错点，必须分清。
> 第一，酸性不同……第二，苯环活泼性不同……

既然语料要区分，工具也应区分——**否则工具与语料口径不一致**，
学生会看到"工具说苯酚是羟基、教材说苯酚是酚"。

### 一处断言方向被反转

`test_acetic_acid_hits_carboxyl_not_ester_or_aldehyde` 的原 docstring：

> 注意：它**也会命中羟基**——这不是 bug。SMARTS `[OX2H]` 只描述
> "连两个原子且带氢的氧"，无法区分醇羟基与羧酸羟基……
> 这是既有 chem 模块的模式粒度局限（见决策登记表 I5）

**这段话在改动后完全失效**。已改写为
`test_acetic_acid_does_not_hit_any_hydroxyl`，
断言方向从"允许误报"反转为"禁止误报"，
并说明为什么这是化学正确性问题。

保留这类"记录已知局限"的测试有价值——
它让局限显式可见。但局限消除后**必须改写而不是删掉**，
否则就成了没有约束的空白。

## 6. 改动后的实测结果

```
醇（C-OH，羟基连 sp3 碳）:
  乙醇          ['醇羟基']
  乙二醇        ['醇羟基']
  叔丁醇        ['醇羟基']
  苯甲醇        ['醇羟基', '苯环']

酚（O-H 直接连芳环碳）:
  苯酚          ['酚羟基', '苯环']
  甲基苯酚      ['酚羟基', '苯环']
  羟基苯甲醇    ['醇羟基', '酚羟基', '苯环']   ← 两者都有，正确

羧酸:
  乙酸          ['羧基']                ← 不再误报羟基
  苯甲酸        ['羧基', '苯环']
  甘氨酸        ['羧基', '氨基']
```

## 7. 容易想当然的两个边界

**① 苯甲酸的 OH 不算酚羟基**
苯甲酸含苯环，直觉上"环上带 OH"，但它的 OH 在 `-COOH` 里，
连接点是 **sp2 羰基碳**而非芳香碳。测试
`test_aromatic_acid_oh_is_not_phenol` 锁定。

**② 同一分子可同时命中两条**
羟基苯甲醇（`Oc1ccccc1CO`）苯环上有酚羟基、侧链有醇羟基，
两者都命中是**正确**的。实测原子索引不重叠：
- 醇羟基匹配 `(8, 7)`
- 酚羟基匹配 `(0, 1)`

验证这一点时我先写错了期望值（以为醇应为 False），
被实测纠正——**它明明有侧链羟基**。测试
`test_molecule_can_hit_both` 现已锁定该行为。

## 8. 未验证的部分

**所有实测都用容器内的 RDKit，未涉及真实模型。** 具体来说：

- 官能团清单**是否覆盖课标全部要求**——本模块只改了羟基，
  其余 10 条未重新评估；
- **酯基的 `[CX3](=O)[OX2H0][#6]` 是否会误判碳酸酯**
  （碳酸酯的 O 也是 H0）；
- 递归否定对**含氮杂环、生物碱**等高中不涉及结构的处理。

这些须由**化学教师审核**（决策项 H13/H18），
本模块的实测只能保证"代码行为符合我列出的期望"。
